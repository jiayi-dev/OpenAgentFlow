# 第一批执行正确性优化

## 目标与边界

修复检索缓存可信语义、融合与精排、索引读路由、多意图部分成功、聊天事务以及工作流截止时间和上下文隔离六项问题。保留前端接口和页面；不自动启动后端；新增 Java 方法、字段和关键逻辑使用中文注释。

## 实施顺序

1. 为冷/热缓存一致、乱序候选和精排池边界补回归测试，再修复 KnowledgeBaseService。
2. 将一次检索绑定到数据库中的索引路由快照，统一模型、Milvus 物理集合、关键词索引及缓存版本；索引激活串行化并补偿失败的别名投影。
3. 为工具与知识混合请求补齐非流式和 SSE 分支，知识不足只影响对应知识回答。
4. 将聊天外部调用移出长事务，创建、完成及失败记录使用明确的短事务边界。
5. 工作流按截止时间返回和取消，禁止对结果未知的副作用节点自动重试，隔离嵌套分支上下文。
6. 统一执行回归、构建和迁移副本检查，更新 README 能力说明，不写修改历史或验证记录。

## 核心验收约束

- 缓存不能改变是否拒答，失效或无权来源不能经缓存放行。
- 排名使用排序后的序号，精排结果不得与未校准规则分数混排。
- 同次检索使用兼容的模型及索引版本，数据库回滚不改变权威读路由。
- 混合请求中的合法工具可执行，知识不足不得编造政策。
- 模型失败仍保留 Run 与 Trace，网络等待不占用聊天数据库事务。
- 超时不会自动重复副作用，分支不能通过嵌套可变引用污染彼此。
